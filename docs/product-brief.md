## 1. 背景與問題

乘客在入閘前後想知道下一班車何時到站，往往要開啟功能繁多的官方 App，經過多層選單才找到班次。常用車站固定的通勤者，每天重複同一組操作。

政府資料一線通（DATA.GOV.HK）已公開港鐵實時班次 API，可以做一個**開啟即見常用車站班次**的輕量 Web App。

**問題陳述：** 香港通勤者需要在數秒內得知指定車站兩個方向的下一班車時間，但現有途徑步驟太多，也不能把常用車站設為首頁。

## 2. 目標用戶

| Persona | 描述 | 主要需要 |
|---|---|---|
| 通勤者阿明 | 每日在固定兩三個車站上下車 | 開 App 即見常用車站，零操作 |
| 不熟路線的訪客 | 遊客或少搭某條線的市民 | 用中文或英文搜尋站名，看得懂往哪個方向 |
| 身處陌生地點的人 | 剛出街，不肯定最近哪個站 | 一按即找到附近車站及其班次 |

> **注意：** 以上 persona 是**假設**，本項目不做用戶訪問，README 會註明這一點。

## 3. 核心用戶故事（MVP）

1. 作為通勤者，我想**收藏常用車站**，下次一開 App 就直接看到它們的班次。
2. 作為乘客，我想**先揀路綫再揀車站**，像看港鐵路綫圖一樣找到車站。
3. 作為訪客，我想用**中文或英文搜尋站名**（例如「將軍」或「tko」），不用知道它屬哪條線。
4. 作為身處陌生地點的人，我想**定位最近的車站**並直接看到班次。
5. 作為任何用戶，我想看到**每個方向最多 4 班車**的終點站、月台和倒數時間，並且**自動更新**。
6. 作為用戶，我想在**中文與英文介面**之間切換。

## 4. 範圍

### 包括（MVP）
- 港鐵重鐵 10 條路綫（AEL、DRL*、EAL、ISL、KTL、SIL、TCL、TKL、TML、TWL），約 97 個車站
- 四種查詢方式：揀路綫→揀站、搜尋站名、收藏常用站、定位最近車站
- 轉車站在同一畫面分路綫顯示（例如金鐘：荃灣綫／港島綫／南港島綫）
- 每 10–15 秒自動更新，並顯示「最後更新時間」
- 中英雙語介面
- 延誤提示（API 回傳 `isdelay: "Y"` 時顯示）

\* DRL（迪士尼綫）有出現在車站名單，但實時 API 是否支援有待 M0 驗證。

### 不包括（今期不做）
- 輕鐵、港鐵巴士、機場快綫以外的其他交通工具
- 路線規劃／轉車建議／車費計算
- 推送通知、用戶帳戶、跨裝置同步
- 原生 App（iOS / Android）

## 5. 功能需求

| ID | 功能 | 優先度 | 驗收標準 |
|---|---|---|---|
| F1 | 班次顯示 | Must | 顯示兩個方向，每方向最多 4 班，包括終點站、月台、倒數；總站只顯示一個方向 |
| F2 | 自動更新 | Must | 每 10–15 秒 refetch；分頁在背景時暫停 |
| F3 | 揀路綫→揀站 | Must | 路綫以官方顏色標示；車站按站序排列 |
| F4 | 搜尋站名 | Must | 中英文、站 code 均可搜，容許部分輸入 |
| F5 | 收藏常用站 | Must | 存於 localStorage；首頁優先顯示收藏 |
| F6 | 中英切換 | Must | 介面文字、站名（來自車站 CSV）、錯誤訊息同步切換；記住選擇 |
| F7 | 定位最近車站 | Should | 用戶授權後列出最近 3 個站及距離；拒絕授權時有清楚說明 |
| F8 | 錯誤與空狀態 | Must | API 失敗、非服務時間、`valid=N` 各有對應訊息，不會白畫面 |
| F9 | PWA（加到主畫面） | Could | M3 處理 |

## 6. 非功能需求

- **速度：** 4G 網絡下首次載入少於 2 秒；Lighthouse Performance ≥ 90
- **無障礙：** Lighthouse Accessibility ≥ 90；倒數時間不只靠顏色表達
- **手機優先：** 以 375px 寬度設計，單手可操作
- **私隱：** 位置只在瀏覽器內計算，不傳送到任何伺服器；不設追蹤
- **品牌：** 不使用港鐵商標；頁尾註明「資料來源：DATA.GOV.HK，本 App 與港鐵公司無關」

## 7. 數據來源（2026-10-22 已實測）

| 資料 | 來源 | 備註 |
|---|---|---|
| 實時班次 | `GET https://rt.data.gov.hk/v1/transport/mtr/getSchedule.php?line={LINE}&sta={STA}&lang={TC\|EN}` | `Access-Control-Allow-Origin: *`；CDN `max-age=10` |
| 車站名單 | `https://opendata.mtr.com.hk/data/mtr_lines_and_stations.csv` | 有路綫、方向、站 code、中英文名、站序；**沒有經緯度** |
| 車站座標 | 自建靜態 JSON（一次性由 OpenStreetMap 匯出） | 約 97 個站，人手核對 |

**回應重點欄位：** `data["{LINE}-{STA}"].UP / DOWN[]` 內有 `dest`、`plat`、`time`、`ttnt`（分鐘）、`valid`；頂層有 `curr_time`、`isdelay`、`status`、`message`。

**倒數計法：** 用 `time − 裝置現在時間` 計到秒，而不是直接用 `ttnt`（只準到分鐘）。

### M0 實測結果（2026-10-22）

| 問題 | 結果 | 對設計的影響 |
|---|---|---|
| DRL 是否支援 | 支援。`DRL-SUN` 只回 `DOWN`（往 DIS），`DRL-DIS` 只回 `UP` | DRL 照常列入 MVP |
| 總站 | 只回一個方向（例如寶琳只有 `DOWN`） | UI 不能假設兩個方向都有 |
| 延誤欄位 | 頂層 `isdelay: "Y" \| "N"`，所有路綫都有 | 實測時全部是 `N`，`Y` 的畫面要用假資料測 |
| 錯誤站 code | `status: 0`，`message: "The contents are empty!"`（英文） | 錯誤訊息要自己翻譯，不能直接顯示 |
| `lang` 參數 | TC 與 EN 回傳的 `dest` 都是站 code（例如 `POA`） | **站名必須來自車站 CSV**，F6 不靠 API `lang` |
| `curr_time` 時差 | 瀏覽器收到時，`curr_time` 比裝置時間慢約 10–15 秒 | 倒數以裝置時間計，否則會多報 10–15 秒 |
| 其他欄位 | `source`（`+`/`-`，意思未明）；東鐵綫有 `route` | MVP 不使用 |
| 瀏覽器 CORS | 由 `localhost` 直接 fetch 成功 | 確認不需要後端 |

## 8. 技術方案

- **前端：** React + Vite + TypeScript
- **數據抓取：** TanStack Query（polling、快取、錯誤重試）
- **靜態資料：** build 時將車站 CSV 及座標轉成 JSON，打包進 App
- **狀態儲存：** localStorage（收藏、語言）
- **部署：** GitHub Pages（GitHub Actions 自動 build）
- **不需要後端：** API 已開放 CORS，瀏覽器可直接呼叫

```
瀏覽器 ──(每 10–15 秒)──> rt.data.gov.hk 班次 API
   │
   ├─ stations.json（build 時由 CSV 生成）
   ├─ coords.json（人手整理）
   └─ localStorage（收藏、語言）
```

## 10. 風險與限制

| 風險 | 影響 | 應對 |
|---|---|---|
| API 格式或 endpoint 改變 | App 無法顯示班次 | 用型別驗證回應；失敗時清楚顯示錯誤 |
| 非服務時間沒有資料 | 用戶以為壞了 | 專門的「非服務時間」狀態 |
| 車站座標人手整理出錯 | 定位結果不準 | 用港鐵站出口座標核對；寫測試檢查每個站都有座標 |
| 定位權限被拒 | F7 不能用 | 改為引導用戶搜尋 |
| 轉車站跨多條線 | 版面複雜 | 同一頁用分頁或分段顯示各路綫 |
| 即日完成，時間不夠 | 部分功能做不完 | 按第 11 節的次序做；刪減線以下（F9、Lighthouse）可留待課後 |
| persona 未經驗證 | 功能未必切合真實需要 | README 註明 persona 為假設 |
